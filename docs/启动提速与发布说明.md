# 启动提速与版本发布说明

本文对应 1.2.0 版本的启动优化：把「启动时联网拿 Plotly / SheetJS」和「启动时加载 NumPy / SciPy」两件事都去掉了。

## 1. 这次改了什么

| 问题 | 原来 | 现在 |
| --- | --- | --- |
| Plotly / SheetJS | `index.html` 顶部用 `<script src="https://cdn.plot.ly/...">`、`https://cdnjs.cloudflare.com/...` 同步加载，断网或网络差时一直等到超时，页面白屏 | 两个库放进 `src/vendor/`，随程序一起分发，从本地读取，断网可用、启动不再等网络 |
| NumPy / SciPy | `build_exe.py` 顶部 `from trpl_fit import ...`、`from ups_fit import ...`，一启动就把 NumPy、SciPy（含 2 个 OpenBLAS 动态库）全读进内存 | 改为在第一次点「拟合」时再 `import`，不做拟合就完全不加载 |
| 页面加载方式 | 把 HTML 读成字符串交给 `create_window(html=...)`，相对路径资源无法解析 | 改为 `create_window(url=index.html 路径)`，由 pywebview 的本地 HTTP 服务提供页面，`vendor/` 相对路径才能正常加载 |
| 首次/二次启动差别 | WebView2 每次都要重新建立运行时环境、没有可复用的缓存 | 前端资源本地化后不再受网络与 CDN 抖动影响；WebView2 运行时本身的缓存由系统维护 |

打包时不需要额外操作：`packaging/perovskite-engine.spec` 已经把 `src/vendor` 一起打进 `_internal/src/vendor`，
`bottle` / `typing_extensions` / `webview.http` 也作为隐藏依赖写进了 spec（本地 HTTP 服务需要它们）。

## 2. 怎么验证启动变快了

程序内置了启动耗时追踪，默认关闭，只在你手动打开时写日志：

```powershell
$env:PEROVSKITE_STARTUP_TRACE = "$env:TEMP\perovskite-startup.log"
& '.\PerovskiteEngine.exe'
# 关闭窗口后查看
Get-Content "$env:TEMP\perovskite-startup.log"
```

日志形如：

```
   0.412s  main entered
   0.598s  window created, entering webview.start()
   2.031s  ui ready (frontend 812 ms)
```

- `main entered`：Python 解释器、pywebview 已完成导入，`NumPy/SciPy` 尚未加载。
- `ui ready`：页面脚本执行完毕，也就是用户真正能点的时刻。
- 第二次启动通常比第一次快 0.3–1 s，因为系统已经缓存了 EXE/DLL。

对照实验：删掉 `src/vendor` 里的文件、把 `index.html` 改回 CDN 之后再跑一次，就能看到网络带来的差别。

## 3. 发布新版本的正确流程

```powershell
# 在项目根目录执行，例如把版本从 1.2.0 升到 1.3.0
powershell -ExecutionPolicy Bypass -File scripts\build_release.ps1 -Version 1.3.0
```

脚本会依次完成：

1. 把版本号写进 `packaging/PerovskiteEngine.iss`（`AppVersion`）；
2. 检查 `src/vendor` 是否齐全、`index.html` 是否还有 CDN 引用；
3. 用 PyInstaller 重新构建 `packaging/release-dist/PerovskiteEngine`；
4. 用 Inno Setup 生成 `packaging/installers/PerovskiteEngine-Setup-1.3.0.exe`。

发给用户时**只发这个安装包**，不要只发 `PerovskiteEngine.exe`：
`_internal` 目录里是 Python 运行时和依赖库，缺了它程序起不来。

安装包使用固定的 `AppId` 和安装路径（`%LOCALAPPDATA%\Programs\Perovskite Engine`），
新版可以直接覆盖安装，用户不必先卸载旧版。

## 4. 还能继续优化的地方

- **数字签名**：没有签名时，从微信/网盘下载的安装包会被 SmartScreen 拦一次，杀毒软件也更容易全盘扫描。
  这是「别人第一次打开特别慢」的主要原因之一，需要购买代码签名证书后对 exe 和安装包签名。
- **让用户加白名单**：内网/单位电脑可在 Defender 里对安装目录添加排除项，能明显减少首次启动的磁盘扫描。
- **自动更新**：需要版本清单服务（例如一个 JSON 文件 + 安装包下载地址），程序启动时比对版本、提示下载。
  目前未实现，可后续按需增加。
- **进一步瘦身**：`_internal` 里两个 OpenBLAS 动态库各约 36 MB（NumPy 和 SciPy 各带一份），
  它们是拟合功能必需的；如果以后拆分「精简版（不含拟合）」和「完整版」，精简版可以降到约 60 MB。

## 5. 1.3.1 启动稳定性：.NET 运行时与错误提示

Windows 上 pywebview 通过 **pythonnet** 加载 .NET 的 WebView2 控件。pythonnet 默认用
.NET（CoreCLR）宿主；个别电脑上宿主初始化失败，会直接弹出
`Failed to initialize Python.Runtime.dll`，窗口根本出不来。

1.3.1 的处理方式（`build_exe.py`）：

1. **先定运行时，再导入 pywebview**：顺序为 环境变量 → 上次成功记录 → 默认 `netfx` → `coreclr`；
   绝不在 CLR 半初始化之后再切换。
2. **默认用 `netfx`**：Windows 10/11 自带 .NET Framework 4.8，不依赖 hostfxr，实验室电脑上更稳；
   成功一次后写入 `%LOCALAPPDATA%\PerovskiteEngine\dotnet-runtime.txt`，下次直接复用。
3. **写启动日志**：`%LOCALAPPDATA%\PerovskiteEngine\logs\startup.log`，每次启动记录
   运行时选择、成功/失败原因、窗口尺寸、WebView2 版本。超过 256 KB 自动轮转为 `.1`。
4. **失败给中文说明**：不再抛英文堆栈，而是系统消息框提示“未能加载 .NET / WebView2 环境”，
   并给出日志路径与两条处理建议（.NET Framework 4.8、WebView2 运行时）。

排查时先看日志：

```powershell
Get-Content "$env:LOCALAPPDATA\PerovskiteEngine\logs\startup.log"
```

强制指定运行时可临时设置环境变量（一般不需要）：

```powershell
$env:PEROVSKITE_DOTNET_RUNTIME = "coreclr"   # 或 netfx
```

## 6. 关于 DPI 缩放（重要，别再踩）

1.3.1 曾尝试“声明 DPI 感知 + 按 125% 放大窗口”，实测反而把右侧工具栏挤出窗口：
WebView2 会把物理像素当 DIP 再放大一次，页面按 1.25 倍渲染却只显示左侧约 1362 CSS 像素。

现在的做法是 **保持 DPI 不感知、窗口固定 1366×768 逻辑像素**，由 Windows 统一缩放。
在 125% 缩放的 1920×1080 屏幕上实测：CSS 视口 1348 px，工具栏右边缘 1305 px，完整可见。

另有一条经验：用 `PrintWindow` 截图会得到 DPI 不感知的位图（1362 px 宽），看起来像“被裁切”，
其实只是截图方式的问题。判断真实布局请用 WebView2 的远程调试：

```powershell
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS = "--remote-debugging-port=9222"
# 启动软件后，用 Playwright connectOverCDP('http://127.0.0.1:9222') 读取 window.innerWidth / devicePixelRatio
```

## 8. 外观设置（1.4.0）

侧栏底部「⚙ 设置」→ 外观（1.4.1 起从顶栏按钮行移到这里，常驻可见）：

- **明暗**：浅色 / 深色 / 跟随系统（读取 Windows 的 `prefers-color-scheme`）；
- **强调色**：海蓝（默认）/ 深青 / 石墨 / 靛紫 / 暖砂；
- 选择写入 `localStorage` 的 `perovskite-workstation-appearance-v1`，下次启动自动应用，首屏不闪白；
- 图表跟随主题：`Plotly.react/newPlot` 被包了一层，自动注入背景、网格、坐标轴颜色与色序；
  深色下把浅色色板映射到对应的高亮色，切回浅色时按原始色还原。

实现落在 `src/index.html` 的 `<style id="appearance-theme">` 与文件末尾的主题引擎里，
没有改动原有 CSS，默认值刻意等于 1.3.1 的外观，所以不选设置时界面与以前完全一致。
